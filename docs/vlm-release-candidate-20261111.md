## 一、用户实际获得什么

SeetheTruth 是模型计算机制学习工具。用户可以在同一自由计算图上连接积木、验证形状、执行小规模数值、查看论文依据及部分训练和推理过程；支持的计算子图可以导出独立 NumPy/PyTorch CPU 程序。不同算子的执行、梯度和代码生成覆盖范围由 [能力矩阵](../capabilities.html) 分别声明。

此次 VLM 增量增加四个有界数值积木、四条图课程和一门共享课程。学习者可以从合成像素与文本 Token 出发，观察视觉前缀、独立 Cross-Attention、Token 平均压缩，以及文本 Query 的 Patch Top-K 选择与 Dense/稀疏读出误差。图中的线性权重是教学权重，尚未接入预训练视觉语言模型、真实图片解码或自然语言问答质量评分。

**首次体验：**

```bash
git fetch origin
git switch --track origin/feat/vlm-unified-learning-20261111
python atlas_server.py --port 8765
```

- `http://127.0.0.1:8765/teaching.html?course=vlm`：课程入口和机制解释
- `http://127.0.0.1:8765/learn.html?mission=extension_vlm_early_fusion`：视觉前缀
- `http://127.0.0.1:8765/learn.html?mission=extension_vlm_query_patch_selection`：稀疏选择与误差

在工作台选择微型数值模式，运行后选中具体节点观察数据。当前 Android Workflow 生成 **Debug 签名离线教学 APK**；它可供手动测试，但不是应用商店发行版。

## 二、科研证据与功能边界

| 科学或工程问题 | 真实验证 | 可以做出的结论 |
| --- | --- | --- |
| 算子是否真正执行 | Node 数值/Shape/失败输入合同 | 在给定张量范围内产生可重复中间值 |
| Cross-Attention 是什么 | 文本 Query 与视觉 K/V 的独立标量对照 | 输入语义、Softmax 与残差的当前图实现 |
| Patch 是否按文本条件被选择 | Top-K 数值、Query/Rank/Patch 来源映射 | 被选中的视觉索引和二维网格位置 |
| 稀疏是否接近 Dense | TopK=2/4、独立 NumPy/PyTorch CPU Float64 与 MSE | 单层向量读出误差及数学分解 |
| 工作台是否可使用 | Chromium 桌面/390px 视口交互、失败路径、课程与原页面回归 | 这些浏览器视口下的主要交互正常 |
| Android 是否可安装 | Gradle Debug 构建、离线资源审核、包内容检查 | 得到可安装的测试工件，未证明全部真机交互体验 |

VLM 的局部 MSE 并不是 Grounding 准确率、最终语言质量或视频效果。Top-K 示例先算全部 QK、再计算选中分支与全量分支，既没有减少全部分数计算，也没有测量 GPU 加速。源码参照与实际行为由 [VLM 计算说明](vlm-learning-architecture.md) 和相应 Node/Python 测试定位。

工作流通过必须绑定**某次实际提交**。在本轮重写前，`ea8caaef3dbf4301eee87321d4553265f6d4503d` 的八条必需 PR Actions 曾全部成功；当前新的教学页面与数学说明需要根据 [PR Checks](https://github.com/Qesire/SeetheTruth/pull/105/checks) 再验收。历史 TinyStories 模型采样与复跑证明既有特定模块的运行来源，不能作为 VLM 真实模型证据。

## 三、设计审查：能否完成第一次实验

当前课程首页将**所选课程、数学解释和进入实验**组织为一次操作；手机视口优先显示当前课程详情，列表保留用于切换，其他实验室收进可展开导航。积木按钮、课程筛选、键盘聚焦与失败反馈沿用现有控件，课程内容仍由唯一的 `teaching_curriculum.js` 提供。

浏览器测试核对课程链接、手机端内容顺序、导航展开和焦点保留。手机视口截图只支持视觉排版结论，**真实 Android 触屏的连线、缩放和系统 WebView 差异仍需真机验证**。完整科研工作台还有大量高级选项；内部试用应重点记录首次使用者是否能发现数值运行、找到被选节点、理解数学结果与源输入的联系。

## 四、版本判断与实际发布门槛

| 阶段 | 判断 | 仍需完成 |
| --- | --- | --- |
| 内部 Alpha 候选 | 已具备可执行核心和自动化验证基础 | 本轮最终 HEAD 全绿、手动首开与受控用户试用 |
| 公开 Alpha | **暂不发布** | 所有者确认许可证或等效再分发授权、合并后 `main` 和 Tag 验证、发行说明与工件 |
| Beta | **尚无足够用户证据** | 非作者首轮任务完成、Android 真机操作、主要反馈修复及兼容性测试 |
| 稳定 v1.0 | 后续版本 | 版本化图格式、长期维护策略和跨版本功能保证 |

仓库根目录目前**没有 `LICENSE`**，也没有已发布 GitHub Release。这一法律与发布动作必须由项目所有者确定，不能由代码测试结果替代。候选版本号 `v0.1.0-alpha.1` 尚未实际创建。

公开发布的顺序应为：决定授权与第三方权利范围；用最终 SHA 通过全部必需工作流；完成干净安装、桌面首次任务与 Android 真机验证；审查并合并 PR；在 `main` 与版本 Tag 上复核；最后发布说明、测试 APK 范围与反馈渠道。

**当前最有价值的下一步**是邀请少量非开发者完成“进入 VLM → 运行前缀 → 找到文本读出 → 对比 Top-K 误差”的连续任务，并记录操作时间、错误点与无法理解的公式位置。真实使用行为比再增加一批没有交互动机的积木更能决定何时进入 Beta。
