# Rank-4 broadcast and reduction: independent gradient certificate

## Why this fixture matters

Matrix shape agreement does not establish correct **axis reductions in the backward pass**. A single singleton-channel bias can be consumed by many tokens and heads, and a token-axis reduction must redistribute its upstream gradient to every input token. This case certifies the existing computational rules against actual standalone PyTorch CPU, without adding a second operator runtime.

## Source-derived graph

```text
θ_source [1,2,3,2] ────────┐
                           ├── nd_broadcast_add ── [1,2,3,2]
θ_bias   [1,1,1,2] ────────┘                 │
                                             ▼
                                   nd_reduce_sum(axis=2)
                                        [1,2,1,2]
                                             │
θ_target [1,2,1,2], frozen ──────────────── nd_mse
                                             │
                                           [1,1]
```

The exact source implementations are `nd_tensor.js` (rank-4 broadcast and keepdim reduction), `nd_autodiff.js` (broadcast un-reduction and reverse of token-axis sum), `learning_lab.js` (graph evaluator), and `torch_codegen.js` (independent Python graph lowering). These files and the fixture are included in the SHA-256 source digest.

For `S∈R^{1×2×3×2}`, `b∈R^{1×1×1×2}`, `Y_{h,t,d}=S_{h,t,d}+b_d`, and `U_{h,d}=Σ_tY_{h,t,d}`, the gradients must satisfy

```math
\frac{\partial L}{\partial S_{h,t,d}} = \frac{\partial L}{\partial U_{h,d}},
\quad
\frac{\partial L}{\partial b_d}=\sum_h\sum_t\frac{\partial L}{\partial U_{h,d}}.
```

The bias gradient must accumulate across **both** head and token axes. This differs from copying the upstream tensor, and fails if `nd_broadcast_add` forgets to unbroadcast its inputs or `nd_reduce_sum` loses the keepdim axis. Original port names `a,b,x,prediction,target` and node identity remain unchanged.

## Executable checks

- `tests/nd_broadcast_certificate_contracts.js` checks every source output shape, bias accumulation over the six consumers per feature, each individual token's reverse gradient, centered difference on a specific bias element, exported source availability and incompatible broadcast-axis rejection.
- `tests/torch_operator_certificate_ledger.js --check` now enumerates actual rank-2 and rank-4 trainable coordinates using `ND.indices`, compares every present forward and reverse coordinate to independent standalone PyTorch 2.6.0+cpu Float64 autograd, and performs centered differences for all eligible trainable coordinates in the v2 fixtures.
- `tests/operator_certificate_registry_contracts.js` checks per-fixture identity and anti-forgery constraints; `tests/browser_unified_specialists.py` verifies desktop and phone capabilities UI displays the new specific `nd_broadcast_add`, `nd_reduce_sum`, `nd_parameter`, `nd_mse` evidence.

All newly tested cases continue to report `notGeneralized:true`. There is no automatic upgrade of the generic kind's VJP, exporter or GPU capability. The signed-off ledger must be generated by actual CI PyTorch execution on the **final commit**, not by a hand-written declaration.

## Boundaries

This validates the concrete singleton-bias and token keepdim axes, not all broadcasting alignments, mixed-rank output behaviors or N-D matmul with broadcasting. A future independent fixture should challenge batch/head broadcasting in batched matmul and the gradient reductions through shared and repeated KV heads. `nd_broadcast_mul` requires verified independent exporter support before entering the same certificate contract; the registered JS rule alone is insufficient.
