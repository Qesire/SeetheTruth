# Source-pinned operator case certificates — v1

## Objective and truth boundary

A static operator kind declaration, a successful code-generation allowlist entry, a numerical JS teaching path, and **independently executed PyTorch CPU evidence for a precise graph/shape** are four different claims. The certificate system records the last claim **only for actually executed and checked coordinates**, and presents it beside the unchanged capability matrix. It does not convert all 150 kinds into generic gradient-verified operators.

## Concrete execution that produced the v1 certificate

`tests/torch_operator_certificate_ledger.js` executes the existing `coordinate_training_graph` fixture through two separate numerical paths:

1. The original LearningLab Float64 graph Forward and GraphAutodiff full-loss VJP.
2. Standalone Python generated by the existing `torch_codegen.js`, run in a real pinned PyTorch `2.6.0+cpu` interpreter. The Python side uses `torch.autograd`, not JS source functions. It retains intermediate gradients and returns the Forward and Loss-adjoint tensors for all participating graph nodes.
3. Independent centered parameter finite differences for both 2×2 trainable matrices, covering eight scalar coordinates.

The test checks each participating forward and reverse element numerically, rejects missing/nonfinite PyTorch gradients and rejects errors above tolerances. It then emits exactly six scoped kind records (add, matmul, mse, parameter, scale, square) covering eight graph nodes, **29 forward tensor coordinates and 25 loss-adjoint coordinates**, plus eight finite-difference parameter coordinates. The fixture also contains a frozen target parameter: it is Forward-checked but does not receive a fictitious trainable gradient.

Numerical error fields are reproducible **proved upper-bound buckets** (e.g. \`≤1e-12\`), not raw bitwise-exact observed maxima; PyTorch/JS differences of a few 1e-17 do not invalidate a successful independent oracle on another CPU runner. A true error above the tolerance still fails the generator before it emits any artifact.\n\nEach certificate specifies only `fixtureId`, `caseIds`, observed coordinate counts, shape at each node, actual pinned backend, error bounds and `notGeneralized:true`. A passing MatMul on a 2×2 input does not certify arbitrary batch shapes, higher-dimensional broadcasting, non-smooth branches, all optimizers or GPU kernels.

## Reproducibility and invalidation

```text
Original JS graph + full-loss VJP     generated standalone PyTorch CPU
             |                                   |
             +------ numerical comparison -------+
                             |
         tests/torch_operator_certificate_ledger.js
                | --write / --check / --emit
                v
      operator_certificates_data.json
      operator_certificates_data.js
                |
      operator_certificate_registry.js (validation)
                |
      SeetheTruthCapabilities.matrix().rows[].certifiedCases
                |
      capabilities.html (scoped evidence, never universal status)
```

The generator includes SHA-256 hashes of the operator catalog, LearningLab, GraphAutodiff, objective, code generator, selected training proof source, fixture and test generator itself, together with a combined `sourceDigest`. No `generatedAt` clock is included, so an identical measured build emits identical artifacts. Changing any pinned source invalidates the checked-in certificate until the pinned CPU test is rerun and the artifact regenerated. The hashes detect source drift and accidental content edits, **not malicious authorship or independent cryptographic attestation**.

**Regeneration (requires Node 22, Python 3.11, PyTorch 2.6.0+cpu):**

```bash
node tests/torch_operator_certificate_ledger.js --write
node tests/torch_operator_certificate_ledger.js --check
node tests/operator_certificate_registry_contracts.js
```

The `torch-export.yml` workflow installs the pinned CPU backend and runs `--check` on the exact source of the PR. The ordinary evidence contract validates the serialized format, per-node/per-kind counts and actual pinned source-file hashes without needing PyTorch. Browser and Android load the generated JS mirror and show the source digest. A downloaded JSON file and its browser mirror must correspond byte-for-byte to the computed object.

The browser is a **read-only viewer of an evidence artifact committed with the repository**; it does not execute Python or independently check the source SHA-256 at page load. The CI `--check` guarantees consistency only for a GitHub commit whose checks succeeded. A changed, unchecked local build must not be represented as having the repository's successful CI evidence.

## Capability semantics

`SeetheTruthCapabilities.matrix()` continues to return `DECLARATIVE_NOT_EXECUTED` as the general inventory evidence tier. `row.capability.localVjp.verification` and `row.capability.torchExport.verification` remain `not_attested` for a universal claim. New fields `certificateSummary` and `row.certifiedCases` represent actual independent, *fixture-scoped* cases only.

The capabilities page has an **已独立执行测试案例** filter and a detail section containing the fixture, backend, forward/backward coordinate counts, scope warning and source digest. Kinds with no executed certificates explicitly state so. Tests on desktop and phone verify that the general status does not silently become `verified`.

## Adding another test case

Use a small but decisive DAG exercising the concrete operator semantics and expected corner case. Define input values, named axes and ports, shapes, loss, trainable/frozen sources and at least one discriminating negative case. Run JS through the **existing** interpreter and export the **same graph** as independent standalone PyTorch CPU. Compare all involved outputs and gradients, not just the final loss; for a trainable case, verify parameter coordinates with finite differences as appropriate.

Extend the ledger generator to explicitly enumerate the new fixture and all proved coordinates. It must fail on an unsupported lowering or missing derivative instead of adding a guessed success. Regenerate artifacts from a pinned CPU environment and only merge after the final HEAD passes source-digest, numerical, browser and Android checks.
