01 · GQA / MHA：KV Cache 成本

GQA 让多个 Query Head 共享 KV Head。存储量 = 2 × 层数 × Batch × 历史 token 数 × KV Heads × Head Dim × 每元素字节。Head 个数改变的是 KV 存储，不自动证明推理延迟会成比例下降。

论文：GQA (2023)。适用条件：KV cache 访存或存储成为瓶颈；不代表训练计算同幅下降。

02 · MoE：总参数与活跃参数

以无 bias 的 SwiGLU 专家为示例，每位专家的 gate/up/down 参数数为 3 × hidden × intermediate。Top-k 每 token 仅选若干路由专家，但 router、负载均衡、通信和实际批量效率不计入。

参考：Sparsely-Gated MoE (2017)。设计目的：增加条件参数容量而不让每 token 激活所有专家；通信、路由分布和计算密度决定实际性能。

03 · Loop Transformer：共享权重与循环步数

计算同一个 Block 多次，并跨迭代共享参数。共享权重不等于省掉迭代算力。以下只统计 Q/K/V/O 投影与门控 FFN 的参数、每 token 核心投影 FLOPs；不包含注意力矩阵运算。

参考：Universal Transformers。循环共享降低权重存储规模，并不能保证收敛、精度或每 token 延迟改善；自适应退出需要额外状态与停止准则。

所有结果均为解析公式的确定性成本估计，不是实测延迟、GPU Kernel 统计或对某个开源模型的源码确认。
